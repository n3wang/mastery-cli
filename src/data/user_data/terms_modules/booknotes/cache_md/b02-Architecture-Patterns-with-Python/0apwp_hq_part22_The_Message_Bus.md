#### Event-Driven Architecture and Message Bus
Background context: The message bus in this architecture is responsible for handling events and dispatching them to appropriate handlers. It now collects events from the unit of work (UoW) and processes them in a queue-based manner. This introduces a one-way dependency from the UoW to the message bus, removing circular dependencies.
:p How does the message bus process events and manage new events generated during handling?
??x
The message bus starts with an initial event in a queue. It processes events one by one by popping from the front and invoking their corresponding handlers. After each handler completes, it collects new events generated during that handler’s execution using `uow.collect_new_events()` and adds them to the queue. This continues until all events in the queue are processed. This ensures that all side effects (new events) are handled in a predictable order.

#### Code Example: Message Bus Logic
Background context: The message bus logic is implemented as a loop that processes events in a queue, invoking handlers and collecting new events. This approach supports a chain of event processing where new events can trigger additional handlers.
:p Can you explain the logic in the `handle()` function in the message bus?
??x
The `handle()` function in the message bus initializes a queue with the initial event. It processes events in a loop, popping from the front of the queue and invoking handlers mapped to the event type. After each handler, it collects any new events generated by calling `uow.collect_new_events()` and extends the queue with these events. This loop continues until all events in the queue are processed. This ensures that all cascading effects of event handling are properly managed.
```python
def handle(event: events.Event, uow: unit_of_work.AbstractUnitOfWork):
    queue = [event]
    while queue:
        event = queue.pop(0)
        for handler in HANDLERS[type(event)]:
            handler(event, uow=uow)
        queue.extend(uow.collect_new_events())
```

#### Code Example: Collecting Events from UoW
Background context: In the `AbstractUnitOfWork`, the `collect_new_events()` method replaces the older `publish_events()` method. Instead of directly publishing events, it yields them for the message bus to handle.
:p How is `collect_new_events()` implemented in the unit of work?
??x
The `collect_new_events()` method iterates through products that have been seen during the unit of work. For each product, it pops events from the product's event queue and yields them. This method is used by the message bus to gather all newly generated events after each handler finishes. It avoids direct coupling to the message bus and instead provides a clean way for the message bus to collect events.
```python
def collect_new_events(self):
    for product in self.products.seen:
        while product.events:
            yield product.events.pop(0)
```

#### Message Bus Logic: Handling Events and Collecting Results
The message bus processes events in a queue-based manner, executing all registered handlers for each event. After each handler runs, it collects new events raised during processing and continues processing until no more events remain. The key modification is returning a list of results from the handlers.

:p What is the core logic of the updated message bus?
??x
The core logic of the updated message bus involves:
1. Initializing an empty list `results` to collect return values.
2. Using a queue to process events one by one.
3. For each event, iterating through registered handlers and calling them.
4. Appending the return value of each handler to `results`.
5. Collecting any new events generated by the unit of work (`uow.collect_new_events()`) and adding them to the queue.
6. Returning the collected results after processing all events.

Code snippet:
```python
def handle(event: events.Event, uow: unit_of_work.AbstractUnitOfWork):
    results = []
    queue = [event]
    while queue:
        event = queue.pop(0)
        for handler in HANDLERS[type(event)]:
            results.append(handler(event, uow=uow))
        queue.extend(uow.collect_new_events())
    return results
```

This ensures that the message bus not only processes events but also returns meaningful outputs from the handlers.
