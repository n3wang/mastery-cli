#### Supervised vs Unsupervised Learning
In supervised learning, models are trained on labeled data, where each input has a corresponding output label. In contrast, unsupervised learning works with unlabeled data, aiming to discover hidden patterns or structures. While unsupervised learning has potential, most models in production today are supervised because labeled data is essential for performance.

:p Why are most ML models in production supervised?
??x
Most models in production are supervised because they require labeled data to learn meaningful patterns. Supervised learning works well for tasks like click-through rate prediction or recommendation systems, where labels are naturally available. However, in many domains, natural labels are unavailable or expensive to obtain, making labeling a critical bottleneck.

#### Data Lineage
Data lineage tracks the origin and history of data samples, including how they were labeled and by whom. It helps in identifying potential biases or issues in the data, such as sudden increases in incorrect labels, and supports debugging model failures.

:p Why is data lineage important in ML?
??x
Data lineage is crucial for tracking the origin and quality of data samples. It helps detect biases, debug model failures, and ensure that models are trained on consistent, high-quality data. For instance, if a model starts underperforming, data lineage can reveal whether the issue stems from a recent influx of low-quality labels.

#### Weak Supervision Overview
Weak supervision is a technique used in machine learning to generate training labels without relying on expensive hand-labeled data. Instead of manual labeling, it uses noisy heuristics or rules, often derived from domain expertise, to automatically label data. These heuristics are encoded in labeling functions (LFs), which can be applied at scale to large datasets. This approach helps overcome the challenge of acquiring sufficient high-quality labeled data, especially in domains where labeling is costly or time-consuming.

:p What is the core idea behind weak supervision?
??x
The core idea of weak supervision is to use domain knowledge expressed as noisy heuristics (labeling functions) to automatically generate training labels for machine learning models. These heuristics are often imperfect and may conflict with each other, but they can be combined using probabilistic models to produce more reliable labels than raw heuristics alone.

#### Labeling Functions (LFs)
Labeling functions (LFs) are rules or heuristics written by domain experts that assign labels to data samples. They are the building blocks of weak supervision. Each LF takes a data sample as input and returns a label or a " abstain" if it cannot confidently label the sample. LFs can be based on keywords, regular expressions, database lookups, or even predictions from other models. Since LFs are derived from heuristics, they can be noisy and inconsistent.

:p How are labeling functions used in weak supervision?
??x
Labeling functions (LFs) are used to automatically label data samples in weak supervision. Each LF encodes a heuristic rule and is applied to a dataset to generate noisy labels. These labels are then combined using a model that estimates the accuracy of each LF and resolves conflicts between them. The result is a cleaned set of pseudo-labels that can be used for training a machine learning model.

#### Noisy Labels in Weak Supervision
In weak supervision, labeling functions are inherently noisy because they are based on heuristics that may not always be accurate. For example, one LF might label a note as “EMERGENT” because it contains a keyword, while another LF might label the same note as “NOT_EMERGENT” due to a contradictory rule. These conflicting labels must be resolved using a model that estimates the reliability of each LF.

:p Why are labels generated by labeling functions noisy?
??x
Labels generated by labeling functions are noisy because heuristics used in LFs are often imperfect and may not generalize well to all data. For example, a keyword like “pneumonia” might be present in a note but not indicate an emergent case. Additionally, multiple LFs might apply to the same data point and give conflicting labels, making it necessary to combine them using probabilistic models to estimate true labels.

#### Combining Labeling Functions
To effectively use labeling functions, their outputs must be combined to produce a more accurate set of pseudo-labels. This is typically done using a probabilistic model that estimates the accuracy of each LF and weights them accordingly. The model considers the correlation between LFs and resolves conflicts between them. This process is often implemented using tools like Snorkel, which provides a framework for combining LFs and training models on the resulting pseudo-labeled data.

:p How are labeling functions combined to reduce noise?
??x
Labeling functions are combined using a probabilistic model that estimates the accuracy of each LF and resolves label conflicts. The model assigns weights to each LF based on how often it agrees with other LFs and how well it aligns with the expected output. Tools like Snorkel implement this process by estimating LF accuracy and generating a cleaned label distribution for each data point, which can then be used for training.

#### Weak Supervision Overview
Weak supervision is a method for labeling data using programmatic rules (labeling functions) instead of manual annotation. It allows leveraging domain expertise encoded in heuristics without needing full human labeling. This is particularly useful when privacy is a concern, since only a small subset of data needs to be labeled manually to write labeling functions, which can then be applied to the rest of the dataset. The labeling functions can be versioned, shared, and reused across teams and tasks.
:p What is the main idea behind weak supervision?
??x
Weak supervision uses labeling functions (heuristics or rules) to generate noisy labels for large datasets, avoiding the need for extensive manual labeling. It's especially helpful when privacy constraints limit access to full datasets and when domain expertise can be encoded once and reused. This approach allows scaling labeling efforts without increasing annotation costs or privacy risks.

#### Example of Semi-Supervised Learning Logic
A typical semi-supervised approach might use a clustering algorithm to group similar data points, then assign labels based on the cluster’s dominant label. Another method could be a neural network trained to predict labels while enforcing smoothness in predictions across similar inputs.
:p How might semi-supervised learning be implemented in practice?
??x
One approach in semi-supervised learning is to use clustering to group similar data points and assign labels based on the majority label in each cluster. Another is to train a model (e.g., a neural network) that enforces smoothness in predictions — for instance, by minimizing the loss between predictions of similar inputs. This helps propagate labels from labeled to unlabeled data.

#### Transfer Learning Overview
Transfer learning is a method where a pre-trained model (trained on a base task like language modeling) is reused as a starting point for a new, related task. The base task typically has abundant and cheap training data, and the model is fine-tuned on the target task. This is especially useful when the target task has limited labeled data.

:p What is the main purpose of transfer learning in machine learning?
??x
The main purpose of transfer learning is to leverage knowledge from a pre-trained model on a related task (the base task) and adapt it to a new task (the target task) where labeled data is limited. This is particularly useful when the base task has abundant training data (e.g., language modeling) and the target task has limited labeled examples (e.g., medical image classification).

Transfer learning can be implemented as:
1. Pre-train a model on a base task (e.g., image classification on ImageNet).
2. Freeze or partially fine-tune the pre-trained layers.
3. Train the final layers on the target task.

Example:
```java
// Pre-trained model
BaseModel model = loadPretrainedModel("ImageNet");

// Freeze base layers
model.freezeBaseLayers();

// Add task-specific head
model.addHead(numClasses);

// Fine-tune on target task
model.train(targetDataset);
```

This approach often achieves better performance than training from scratch, especially when data is scarce.

#### Evaluation Considerations in Semi-Supervised Learning
In semi-supervised learning, a challenge arises when deciding how much of the limited labeled data should be used for evaluation. If multiple models are evaluated on the same test set, the best-performing model might overfit to that test set. Alternatively, using a validation set reduces the amount of training data, which may hurt performance if the training set is already small.

:p Why is it important to carefully consider how to allocate labeled data in semi-supervised learning?
??x
In semi-supervised learning, the amount of labeled data is often very limited. If multiple models are evaluated on the same test set, the model that performs best on that test set might have overfitted to it, leading to an overly optimistic performance estimate. On the other hand, using a validation set reduces the size of the training set, which can hurt performance if the labeled data is scarce.

A common strategy is to:
- Split labeled data into training, validation, and test sets.
- Use validation for model selection.
- Reserve test data for final evaluation.

For example:
```java
int totalLabeled = labeledData.size();
int trainSize = (int)(0.6 * totalLabeled);
int valSize = (int)(0.2 * totalLabeled);
int testSize = totalLabeled - trainSize - valSize;

trainData = labeledData.subList(0, trainSize);
valData = labeledData.subList(trainSize, trainSize + valSize);
testData = labeledData.subList(trainSize + valSize, totalLabeled);
```

This careful allocation ensures that model selection is robust and performance estimates are realistic.

#### Fine-tuning a Pretrained Model
After pretraining, a model is fine-tuned on a specific downstream task by adjusting its weights using labeled data from that task. For example, a BERT model pretrained on Wikipedia can be fine-tuned for sentiment classification, intent detection, or question answering. The fine-tuning process typically involves training the model for a few epochs with a smaller learning rate, often starting from the pretrained weights.

:p What is the typical process of fine-tuning a pretrained model for a downstream task?
??x
The typical process involves: (1) loading the pretrained model weights, (2) adding a task-specific output layer (e.g., a classification head), (3) training the model on labeled data for the downstream task using a smaller learning rate, and (4) possibly freezing some of the earlier layers to preserve general features while adapting to the task. This process allows the model to adapt its learned representations to the specific task.

#### Active Learning with Real-Time Data
When active learning is applied to real-time data streams, it allows models to continuously learn and adapt to new patterns as they emerge. This is important in environments where data distribution changes frequently, such as in fraud detection or recommendation systems.
:p Why is active learning particularly powerful in real-time data environments?
??x
In real-time data environments, data distributions can shift rapidly due to changing user behavior, market conditions, or external events. Active learning enables models to identify and label the most informative examples from the stream, allowing faster adaptation and improved performance over time. This dynamic learning approach is more effective than batch training on static datasets.

#### Challenges of Class Imbalance
There are three main challenges caused by class imbalance:
1. Insufficient signal for learning minority classes.
2. Model getting stuck in non-optimal solutions by learning simple heuristics.
3. Asymmetric error costs, where misclassifying a rare class is more costly than misclassifying a majority class.
:p What are the three main challenges of class imbalance in machine learning?
??x
First, models may not get enough exposure to minority classes, especially in few-shot learning scenarios. Second, models may learn a simple heuristic like always predicting the majority class, which can be hard to optimize out of using gradient descent. Third, the cost of misclassification is not symmetric — misclassifying a rare but critical event (e.g., cancer) is far more damaging than misclassifying a common one (e.g., normal lung).

#### Sampling Bias Leading to Class Imbalance
Class imbalance can also arise from biases in data collection or sampling processes. For example, in email spam detection, if most spam emails are filtered out before reaching the dataset, the resulting dataset may have very few spam examples.
:p How can sampling bias cause class imbalance?
??x
Sampling bias happens when the process of collecting data introduces a skewed representation of classes. For example, in email spam detection, if spam emails are filtered out before reaching the dataset, the final training data may contain only a small fraction of spam examples, even though spam is prevalent in the overall email population. This leads to models that underperform on rare but important classes.

#### Labeling Errors and Class Imbalance
Sometimes, class imbalance is caused by human labeling errors or misinterpretations of instructions. Annotators might mislabel examples, especially for rare classes, leading to a false imbalance in the dataset.
:p Can labeling errors contribute to class imbalance?
??x
Yes, labeling errors can artificially create class imbalance. If annotators mislabel rare classes as majority classes or fail to correctly identify rare examples, the dataset will appear imbalanced even if the true distribution is balanced. This highlights the importance of quality control and careful annotation protocols in data preparation.
